Technical depth

Sandbox policy is a tested capability envelope

Run untrusted code only in a disposable, named profile with explicit filesystem mounts, blocked-by-default network, no ambient credentials, non-root identity, process and resource limits, controlled artifacts, timeouts, teardown, and escape telemetry. A container label is not evidence; preserve negative tests for filesystem, network, secret, resource, and lifecycle escapes.

Lab safety boundary

Use a disposable local runtime, synthetic files, fake credentials, inert canaries, and a fake transport that opens no socket. Do not attempt host escape, target a real endpoint, mount personal directories, expose a container engine socket, or put a live secret in the lab. A denied test should prove policy behavior—not execute a real exploit.

The one idea

A model may be manipulated and a tool may be buggy. The runtime therefore starts with no ambient authority and adds only what one declared task needs. A container is packaging and process isolation, not a complete security boundary: it shares a kernel unless a stronger runtime boundary is selected. Document both the controls and what they do not isolate.

Profile skeleton

profileVersion: 1
scope: synthetic-procurement-support
runtime:
  privileged: false
  runAsNonRoot: true
  allowPrivilegeEscalation: false
  readOnlyRootFilesystem: true
  capabilities: { drop: [ALL], add: [] }
  seccomp: RuntimeDefault
  hostPID: false
  hostIPC: false
  hostNetwork: false
mounts:
  - { path: /task/input, mode: ro, source: synthetic }
  - { path: /task/output, mode: rw, emptyAtStart: true }
  - { path: /tmp, mode: tmpfs, maxMiB: 16 }
denyMounts: [home, ssh, cloud-config, devices, docker-socket]
network: { default: deny, broker: fake-no-socket }
secrets: { ambient: deny, liveValues: forbidden }
budgets:
  wallSeconds: 30
  pids: 32
  memoryMiB: 256
  outputMiB: 4
  toolCalls: 8
  retries: 1

Profile rules

  • Pin the runtime type/version, image digest, base OS, architecture, seccomp/AppArmor/SELinux profile, and policy-engine version.
  • Record Linux, macOS, Windows, container, VM, or sandbox differences; do not copy Linux settings to an environment where they have no effect.
  • Treat the container/VM boundary and the tool-policy boundary as separate layers.
  • Validate the effective runtime, not only YAML. Admission, defaults, or launch flags can change it.
  • Fail startup when a required control is unsupported; never silently fall back to privileged or network-open execution.
  • Choose a VM/microVM or dedicated worker for impact that a shared-kernel container cannot tolerate.

Egress and DLP are one decision

An allowlisted host is not permission to send every byte. Resolve and validate the final destination at connection time, re-check each redirect, then apply data-class and purpose policy to the exact request. The lab tests these decisions with strings and a fake transport; it does not contact the destination.

Destination

Allow scheme, canonical host, port, method, path family, resolved address ranges, redirect count, and certificate policy. Deny userinfo, ambiguous encodings, wildcard hosts, private/link-local/loopback/metadata addresses, and destination drift.

Data

Attach tenant, origin, sensitivity, purpose, and approved recipient to model/tool data. Deny secret, cross-tenant, or unapproved derived content even when the destination itself is allowed.

Volume

Cap request and response bytes, rate, concurrency, and total egress. Stop decompression, streaming, and repeated-small-request amplification at bounded limits.

Evidence

Log destination/policy IDs, data labels, byte counts, decision, and reason—not raw secret or content. Scan redacted outputs and evidence with unique inert canaries.

Do not turn a policy test into an escape test

For path, URL, command, and secret cases, pass inert values to the validator and fake adapter, then assert denial and zero recorded effects. Do not run a shell string, follow the URL, touch a host service, or test the container engine. A security course can prove the boundary without demonstrating a weaponized bypass.

Build agent-sandbox-profile.md

  1. Declare the synthetic task, data/effect classes, runtime and image digest, supported OS, threat IDs, owner, review date, and explicitly excluded production use.
  2. Inventory every tool, executable, mount, environment variable, credential handle, network path, child process, and resource budget. Begin with none.
  3. Write the effective runtime profile: identity, privilege, filesystem, namespace, kernel controls, network, secrets, logging, limits, cancellation, cleanup, and stronger-isolation trigger.
  4. Implement local policy fixtures. The fake filesystem has only /task/input, /task/output, and an inaccessible sentinel reference; the fake transport records decisions but opens no socket.
  5. Add paired cases for permitted input/output and denied traversal, symlink, host mount, engine socket, undeclared process, URL/destination, secret/canary, oversized output, timeout, retry, and PID/memory budget.
  6. Inspect the effective runtime and preserve command/config output with sensitive values removed. Prove output cleanup and a fresh empty workspace on the next run.
  7. Record gaps honestly. If the platform cannot enforce a requirement, fail the profile or move the task to a stronger boundary.

Acceptance gate

  • Artifact identifies exact runtime/image/policy versions and shared-kernel limitations.
  • Runtime is non-root, non-privileged, no-escalation, capability-drop-all, read-only root, and default seccomp where supported.
  • No host/PID/IPC/network namespace, device, home, cloud config, or container socket exposure.
  • Only task-scoped mounts and adapters exist; unknown tools/fields/executables deny.
  • Egress is deny-by-default and validates destination plus data class through a no-socket fake.
  • No live secret is present; canary and DLP tests cover every output surface.
  • All resource budgets, cancellation, cleanup, and fresh-workspace behavior are tested.
  • Any unenforceable control has a stronger-runtime decision or blocks completion.

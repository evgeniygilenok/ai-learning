Reference

AI engineering job readiness checklist.

Use this as the compressed reference for turning the roadmap into credible hiring signal.

Positioning

Senior TypeScript/product engineer moving into applied AI systems: RAG, evals, agents, observability, security, and production workflows.

Evidence Matrix

RequirementEvidence
LLM product integrationReal-provider product triage with strict structured outputs, usage telemetry, streaming states, validation, and deterministic failure tests.
RAGQdrant-backed knowledge assistant with chunks, ACL payload filters, citations, answerability, and measured lexical/semantic/hybrid retrieval evals.
EvaluationGolden datasets, CI smoke gate, before/after reports, and failure clusters.
ObservabilityRedacted OpenTelemetry GenAI traces in one hosted backend for model calls, tool paths, latency, usage, and failed release cases.
AgentsReal model-driven controlled workflow plus LangGraph/Postgres rebuild with approvals, retries, durable recovery, and trace-based evals.
MCPWorking MCP server invoked from a real client with confused-deputy, least-scope, approval, and replay tests.
Context engineeringMeasured compaction and just-in-time context assembly with before/after tokens, latency, and outcome quality.
Tool safetyValidated, authorized, approval-gated, idempotent, and audited tool execution.
SecurityThreat model, redaction, ACL-aware retrieval, tenant boundaries, and prompt-injection mitigations.
Production readinessClean run path, seed data, CI, env config, health checks, and deployment notes.
Product judgmentUser feedback, adoption notes, scoped fixes, and evals derived from feedback.
Senior communicationArchitecture story, tradeoff memos, demo script, and interview answer bank.

Weekly Learning Loop

  • One lesson or reference pass.
  • One portfolio increment.
  • One eval, trace, or security improvement.
  • One documentation or interview-story update.

Weekly Job Loop

  • Save 5 roles.
  • Contact 3 people.
  • Run 1 interview drill.
  • Apply selectively after the Production Boundaries gate, consistently after the Core Portfolio and Interview gate.

Proof Package

  • One public recruiter link.
  • Public GitHub repo with a case-study README.
  • Hosted/auth-gated synthetic demo.
  • 3-minute demo video.
  • Written eval or recovery deep dive.
  • 10-minute architecture walkthrough.
  • Eval report.
  • Trace walkthrough.
  • Threat model.
  • Deployment notes.

Interview Drills

  • Debug a bad RAG answer from trace to root cause.
  • Design an eval for a new workflow.
  • Choose between RAG, fine-tuning, tools, or a workflow.
  • Threat-model an agent with write access.
  • Explain a cost/latency tradeoff.
  • Walk through a production incident involving model behavior drift.

Common Artifact Rubric

DimensionLevel 3: demonstratedLevel 4: defensible
Correctness and contract integrityValidated behavior plus failure tests.Versioned contracts, negative tests, and recovery evidence.
Evidence and evaluation qualityRepresentative cases, slices, and a failure taxonomy.Human calibration, uncertainty, production feedback, and change history.
Operational and security judgmentMeasured service limits and tested trust boundaries.Threats, detection, response, rollout, rollback, and incident learning.
Explanation and tradeoff clarityAlternatives, evidence, and decision are linked.Audience-aware defense with explicit revisit triggers.

Each core stage needs level 3 in every dimension. The final gate needs at least two level-4 dimensions and none below level 3.

Completion Record

Use starter/evidence/completion-record.md. For every core stage, link working behavior, one failed run and diagnosis, an eval or review result, an operational observation, a decision record, and rubric scores. Completion is based on those inspectable artifacts—not lesson page views.

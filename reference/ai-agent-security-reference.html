AI Agent Security Reference

Architecture invariants, the OWASP agentic taxonomy, control and evidence anchors, release metrics, safe-lab rules, and an incident-response checklist for tool-using agents.

Architecture invariants

1 · Data never grants authority

Prompts, retrieved pages, documents, tool output, memory, and peer messages carry provenance and trust labels. They may supply facts; they cannot expand identity, permissions, policy, or approved intent.

2 · Model proposes; runtime disposes

Deterministic code validates schema, purpose, subject, tenant, object, action, audience, destination, data class, budget, and policy before every privileged sink.

3 · Identity is external to text

Use distinct user, agent, workload, and tool identities. Pass short-lived, least-scope, audience-bound capabilities; never let model-generated text select or impersonate an identity.

4 · Approval binds one exact action

Preview canonical arguments. Bind approver, action hash, scope, amount/recipient, expiry, and one-time nonce. Any mutation or replay requires a new approval.

5 · Isolation exists before the model

Enforce tenant/object authorization in retrieval and again at the sink. Unauthorized bytes must not enter context, trace, cache, scorer, or memory.

6 · Effects are bounded and replay-safe

Use allowlisted tools, canonical validation, idempotency/effect IDs, dry-run, step/time/spend/fan-out limits, and independent reconciliation after ambiguous acknowledgements.

7 · Memory is governed storage

Authorize writes and reads; attach source, tenant, purpose, TTL, confidence, and reviewer state. Quarantine low-trust candidates and support delete, rollback, and derived-data tracing.

8 · Components are inventory, not vibes

Pin and verify models, prompts, skills, packages, images, MCP servers, schemas, registries, and update channels. Fail closed on unreviewed drift.

9 · Execution is contained

Run non-root with read-only base, scoped workspace, dropped capabilities, no host/Docker socket, deny-by-default network, destination/DNS controls, secret broker, DLP, and resource limits.

10 · Containment is independent

Operators can kill, revoke, quarantine, rollback, and reconcile without the model's cooperation. Controls, telemetry, backups, and recovery are tested together.

Always report counts, denominators, intervals, and pins. Zero observed failures is not proof of zero risk; with 0/n independent events, the rough 95% upper rate is about 3/n. State dependence, adaptive-attack limits, moving providers, and uncovered threats.

Safe-lab rules

  1. Use only targets you own or have explicit written authorization to test.
  2. Prefer offline disposable fixtures, fake tools, synthetic identities/data, and inert canaries.
  3. No real mail, payments, refunds, tickets, cloud tenants, customer systems, or production credentials.
  4. Deny network by default; allowlist documentation or dependency access separately from test targets.
  5. Cap requests, cost, time, steps, concurrency, retries, fan-out, storage, CPU, and memory.
  6. Never place live secrets in prompts, cases, logs, screenshots, or evidence bundles.
  7. Keep attack strings inert; do not execute payloads or publish reusable credentials/exploit chains.
  8. Stop on unexpected effects, scope change, another tenant's data, or evidence that the target is not isolated.
  9. Preserve minimal redacted evidence, revoke exposure, notify the owner, and follow responsible disclosure.
  10. Do not treat a course pass as production authorization or compliance certification.

Incident-response checklist

Detect and contain

  1. Open one incident record; name commander, scribe, technical owner, and communications lead.
  2. Record first signal, run/tenant/component IDs, versions, current state, and evidence hashes.
  3. Classify attempted versus realized effect; preserve uncertainty.
  4. Deny new risky actions; kill affected runs/descendants where safe.
  5. Revoke delegated capabilities, sessions, approvals, and exposed secrets.
  6. Quarantine suspect sources, memory, outputs, peers, and component versions.
  7. Reconcile ambiguous effects before any retry.

Scope, recover, learn

  1. Trace provenance and derivation: reads, writes, peers, caches, traces, sinks, and tenants.
  2. Eradicate poisoned state/control gaps through governed paths; keep evidence.
  3. Restore pinned clean components and checkpoint; use compensating effects deliberately.
  4. Run critical deterministic and incident-specific adversarial gates.
  5. Resume a small canary cohort; monitor recurrence and telemetry completeness.
  6. Communicate status/restoration under the incident plan.
  7. Record root path, impact, times, counterevidence, residual risk, owners, due dates.
  8. Add the exact path to threat model, detections, runbook, and release suite.

Before release

  • Threat model/version matches deployed graph.
  • All components and evaluation dependencies pinned.
  • Critical controls enforced outside the model.
  • Paired adversarial/benign cases pass at declared thresholds.
  • No critical unsafe effect, leak, or isolation violation observed.
  • Utility, false blocks, approval burden, latency, and cost reported.
  • Telemetry is redacted, access-controlled, and gap-tested.
  • Kill/revoke/quarantine/rollback/reconcile exercised.
  • Residual risks have owner, acceptance, expiry, and rollback trigger.
  • Release evidence is immutable enough to defend the decision.

Agentic Workflow Engineering Practice

A deeper course for turning agent work from "better prompting" into an engineered system of blocks, gates, tools, reviews, traces, and improvement loops. Each lesson runs about 40 minutes; the paired studio work is where most of the hours go.

Where It Fits

This course is best taken after the main course's Controlled Workflows gate and, for runtime-heavy work, its Hardened Agent Runtime specialization. It turns those foundations into a full engineering practice: design the workflow, encode it in a harness, verify the result, review it, then improve the system from real evidence.

One deliberate ordering choice: implementation strategies (0045) come before planning (0046), following the source outline. You will feel the cost of under-planned implementation first, which is what makes the planning discipline land. If you prefer plan-first, read 0046 before 0045; both orders work.

Outcome

Design workflows as systems

Decompose agent work into blocks with explicit inputs, outputs, transitions, stop conditions, and quality gates.

Outcome

Codify reusable practice

Turn prompts, skills, templates, hooks, commands, and subagents into repeatable engineering assets.

Outcome

Verify beyond vibes

Use deterministic checks first, semantic review where needed, and evals to detect workflow regressions.

Outcome

Operate the loop

Use WAL notes, retrospectives, metrics, and research spikes to improve the workflow without overfitting it.

Completion Gate

  • Workflow graph has named states and transitions.
  • Every block has an input, output, owner, and failure mode.
  • Quality gates include deterministic checks where possible.
  • Risky actions require approval or dry-run behavior.
  • Structured outputs are validated before reuse.
  • Runs have traces, WAL notes, and replayable examples.
  • Review checks target intent, invariants, and edge cases.
  • One retrospective led to a measured workflow change.

What you will demonstrate

The pack covers all named failure types and the module record includes one genuine model failure with a layer-specific diagnosis.

Understand the mechanism

Evaluate the path and the result. A polished final message can hide a denied lookup, an unapproved effect, or an exhausted budget. Start with answerable, missing-evidence, malformed-argument, denied-access, and step-limit cases. Give each case an expected terminal or paused state and an effect count.

A five-case exercise gives you examples to diagnose. It cannot establish a production success rate. Keep deterministic boundary checks separate from human judgments of usefulness and grounding. Preserve case versions so a later change runs against the same inputs.

Trace the diagram against the worked example. Explain who owns each decision and what evidence reaches the next step.

Worked example

A malformed draft has reason:7. The tool validator rejects it before execution, so the failure belongs to proposal shape and runtime validation. An answer with the wrong waiting window has valid JSON but poor grounding, so inspect context and model output. Record state, source IDs, token use, latency, and the layer that should handle each failure.

Guided build · 30 minutes

  1. Run the local practice evaluation and inspect the case expectations and provider fixtures.
  2. Add one case from a genuine model failure observed in earlier sessions. Save a redacted run record and a human explanation.
  3. Compare quality, completion, usage, and latency by case. Name which change belongs in context, model instructions, validation, or authorization.

Your task · 15 minutes

Design one case where the task remains incomplete even though an approved synthetic effect was recorded. Explain how the operator should see that distinction.

Failure investigation · 10 minutes

Set maxCalls to one for a lookup-and-draft task. Inspect the exhausted budget, the preserved lookup, and the absence of an effect. Do not count a clear failure message as task completion.

Before running, predict the state, evidence, and effect count. Then compare your prediction with the record and name the responsible layer.

Exit explanation · 20 minutes

Can another reader reconstruct the failure from the record? Which claims can this small sample support?

Explain the result in your own words and link the supporting command, code change, or redacted record. A missing prerequisite uses the next session's time.

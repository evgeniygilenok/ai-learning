Understand the mechanism

Choose one environment for the course. This example uses Codex project instructions and a repository skill. AGENTS.md describes working rules. A skill describes a repeatable task. The host's sandbox and approval settings determine what commands can actually run. Text in either file does not grant a new permission.

Current Codex documentation describes repository skills under .agents/skills and layered AGENTS.md discovery. Create learner configuration in your own exercise checkout. Before changing shared instructions, inspect existing rules and preserve them. Avoid installing a broad skill merely to shorten a single prompt.

Trace the diagram against the worked example. Explain who owns each decision and what evidence reaches the next step.

Worked example

A 'case-review' skill accepts an event ID, runs the read-only show and record commands, and writes a brief review of pending evidence. If the event ID is absent, it asks for that input and performs no mutation. It has no approve step. A fresh session should be able to invoke it without receiving the previous chat.

---
name: case-review
description: Review one existing synthetic support case by event ID; never approve or execute it.
---
Require an event ID. If missing, ask for it and stop.
Run the practice show and record commands for that case.
Explain evidence, pending proposal, and unresolved questions.
Do not issue approve, reject, cancel, or work commands.

Run shell examples at the repository root. Commented sketches describe learner code to write; they are not additional installed commands.

Guided build · 30 minutes

  1. Record the selected environment, repository root, allowed commands, and host permission settings. Keep credentials outside instructions.
  2. Create the example skill in your learner checkout using the documented skill directory and required metadata.
  3. Invoke it with a valid ID, then with the ID missing, in fresh sessions. Check the artifact and commands used.

Your task · 15 minutes

Package a different repeated read-only repository task. Define its trigger, required input, output artifact, and stopping condition. Demonstrate that the host still controls permissions.

Failure investigation · 10 minutes

Supply the skill a nonexistent case ID. It must report the missing case clearly instead of inventing evidence or creating a replacement case.

Before running, predict the state, evidence, and effect count. Then compare your prediction with the record and name the responsible layer.

Exit explanation · 20 minutes

What belongs in instructions, what belongs in a skill, and what belongs in the host's permission configuration?

Explain the result in your own words and link the supporting command, code change, or redacted record. A missing prerequisite uses the next session's time.

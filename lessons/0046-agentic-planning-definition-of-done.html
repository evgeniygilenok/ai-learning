The One Idea

Agents fill gaps. That is useful when the gap is harmless and dangerous when the gap is a requirement. Planning exists to decide which unknowns can be handled later and which must be resolved now.

A good Definition of Done turns "make it work" into checks the workflow can actually run or inspect. The term comes from Scrum, where it is a formal commitment describing the state work must meet to count as complete (Scrum Guide); for agent workflows the strongest done criteria are executable, which is the same discipline OpenAI's eval guidance applies to model behavior: define good before you build, then check it repeatedly.

Planning Readiness

Ask whether the task has clear intent, affected surfaces, constraints, and known decision owners.

Definition Of Done

Convert success into observable checks: behavior, tests, evals, docs, rollout, and non-goals.

Research Spike

Use a bounded investigation when one unknown blocks responsible planning.

Consensus

Lock the plan as an artifact before the agent spends implementation effort.

Executable Plan Shape

type ExecutablePlan = {
  intent: string;
  assumptions: string[];
  decisionsNeeded: string[];
  definitionOfDone: string[];
  steps: string[];
  checkpoints: string[];
  verification: string[];
  rollback: string;
};

Spike Contract

A research spike should answer one blocking question, have a timebox, state trusted sources or files, and return a decision-ready artifact.

"Research this" is not a spike. "Find which queue library fits our retry and visibility requirements by Friday" is closer.

Interactive Drill: What Does The Plan Need?

"Improve the agent's reliability."

"We cannot choose a storage design because we do not know resume requirements yet."

"The ticket says to notify users, but nobody defined which users or channel."

Try It Cold

Write five Definition of Done bullets for this vague request: "add feedback collection to the knowledge assistant." Make each one checkable, then reveal.

Reveal a model answer
  • Every answer view renders a feedback control; submitting stores rating, comment, answer id, and trace id (verified by an integration test).
  • Feedback rows are queryable by question, source document, and retrieval strategy (verified by one working query in the docs).
  • Submitting feedback never blocks or breaks the answer flow; failures are logged and invisible to the user (verified by a fault-injection test).
  • No PII beyond the existing user id is stored; the retention policy doc covers the new table (verified by review against docs/data-retention-redaction.md).
  • Non-goal stated: no automated retraining or prompt changes from feedback in this iteration.

Compare: can each of your bullets be checked by a test, a query, a doc, or an inspection? "Users can give feedback easily" fails that bar.

Senior Signal

In interviews, strong AI engineers show how they prevent the agent from confidently solving the wrong problem. Planning artifacts are proof of that judgment.

Build Assignment

Take a vague feature request for your portfolio and create an executable plan as a committed file, for example docs/plans/<feature>-plan.md:

  • Write the intent in one sentence.
  • List assumptions and missing requirements.
  • Write five Definition of Done bullets, each checkable.
  • Add one research spike if needed, with its question and timebox.
  • Add checkpoints where the agent must stop and report.

Then hand the plan to your agent and have it attack the plan: "Where would an implementation agent still need to guess?" Fold the answers back in, and note what the attack found in docs/agentic-workflow-course-notes.md.

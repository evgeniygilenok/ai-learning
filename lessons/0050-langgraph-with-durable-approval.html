Technical depth

Framework value is measured at the recovery boundary

Rebuild the same graph, tool, approval, and idempotency contracts rather than inventing a second demo. Use a Postgres checkpointer and stable thread ID, stop at a dynamic interrupt, terminate the process, then resume. Compare hand-rolled and LangGraph behavior on persistence, interrupts, recovery, observability, adoption cost, and failure clarity.

The one idea

A useful framework comparison holds product behavior constant. The model still proposes lookupTransfer and draftEscalation; the runtime still validates, authorizes, pauses, and deduplicates. LangGraph is valuable only if persistence, resume, recovery, and observability become easier to operate and explain.

1. Research

A real model proposes the read-only lookup; code validates and executes it.

2. Propose

The model sees the lookup result and proposes the write tool.

3. Interrupt

LangGraph saves state by thread ID and exposes a serializable approval request.

4. Resume once

A Command resumes the checkpoint; idempotency prevents duplicate effects.

Run the framework path

docker compose -f starter/docker-compose.yml up -d
export OPENAI_API_KEY="..."
export POSTGRES_URL="postgresql://postgres:postgres@localhost:5432/agent_course"
LANGGRAPH_THREAD_ID="case-0050" npm run starter:langgraph
LANGGRAPH_THREAD_ID="case-0050" AGENT_DECISION=approve npm run starter:langgraph

Capture the first interrupt, terminate the process, and resume with the same thread ID. Repeat the resume and prove the completed effect ID remains unique.

Decision record

Score hand-rolled and LangGraph builds from 1-4 on state persistence, approvals/interrupts, crash recovery, trace clarity, testability, dependency/upgrade burden, and adoption cost. Link every score to a command, trace, test, or code location. The record must score level 3+ on the common rubric.

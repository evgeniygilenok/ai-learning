Understand the mechanism

Use the terminal interface throughout this course. It already exposes add, run, show, approve, reject, list, and effects. It reuses the model-driven loop and stores the case between commands. The learner's job is to inspect the complete journey and improve a missing or confusing behavior.

A usable flow must show evidence, uncertainty, and state at the time a person decides. A pendingToolCall is a proposal. An effects-table row is the synthetic execution record. finalText is a model explanation and can fail after the effect exists. Keep these meanings visible.

Trace the diagram against the worked example. Explain who owns each decision and what evidence reaches the next step.

Worked example

Enter the interactive terminal, add a case, run it, and inspect the proposal. Before approve, effects is empty for that case. After approve, the result names the recorded synthetic escalation. Repeat with reject and with an unknown transfer. No source-file edit is required to take either branch.

npm run starter:practice
# At practice>, enter:
add operator-case Why is my pending transfer delayed?
run operator-case
show operator-case
approve operator-case
effects
quit

Guided build · 30 minutes

  1. Walk through the supplied CLI and map every command to the operator journey in your brief.
  2. Implement one small improvement, such as a clearer uncertainty message or a concise evidence view. Reuse processCase and its trusted approval path.
  3. Run ordinary, rejected, and unknown-transfer cases through the improved interface without editing files between steps.

Your task · 15 minutes

Ask someone else to complete a case using only the command help. If unavailable, hide your implementation notes and label the walkthrough as self-review.

Failure investigation · 10 minutes

A proposal appears under a 'completed action' label before approve. Repair the projection and demonstrate both states side by side.

Before running, predict the state, evidence, and effect count. Then compare your prediction with the record and name the responsible layer.

Exit explanation · 20 minutes

How can the operator tell a proposed draft, a recorded effect, and a failed final explanation apart?

Explain the result in your own words and link the supporting command, code change, or redacted record. A missing prerequisite uses the next session's time.

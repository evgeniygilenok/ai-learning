Technical depth

MCP standardizes transport, not authority

Expose the smallest useful schemas and keep actor, tenant, scopes, approval, destinations, and idempotency in trusted server/runtime state. Connect through a real stdio client, then test tenant mismatch, missing scope, replay, and model-supplied attempts to widen authority. Record denied and executed calls without storing secrets.

The one idea

An MCP tool call is still untrusted application input. The server owns authority. A model may choose a tool and propose arguments, but it cannot select its tenant, add scopes, approve its own write, or bypass replay protection.

Schema

Expose only transfer ID, tenant claim, reason, and write idempotency key.

Trusted context

Bind actor, actual tenant, session, scope, and write mode at server startup.

Transport

Use stdio for a local process-spawned client; do not log protocol-breaking output to stdout.

Audit

Record denied and executed requests without tokens, secrets, or raw customer content.

Connect a real client

# Copy starter/mcp-client.example.json into your client's MCP config.
# Start read-only first:
MCP_TENANT_ID=demo-bank MCP_SCOPES=transfers:read npm run starter:mcp

# After explicit approval, prove dry-run behavior:
MCP_SCOPES="transfers:read,escalations:draft" \
MCP_WRITE_MODE=dry-run-approved npm run starter:mcp

Use Claude Desktop/Code, Cursor, or another real MCP stdio client. Capture the client name/version, configuration, tool listing, invocation result, and server audit ID.

Required fail-closed tests

  • Confused deputy: request other-bank while the server is bound to demo-bank.
  • Scope minimization: invoke draftEscalation with only transfers:read.
  • Self-approval: add an unknown approval argument and prove strict schema/runtime checks reject it.
  • Replay: repeat an approved write idempotency key and prove the effect is replayed, not duplicated.

Build assignment

Run both tools from the client, preserve one allowed lookup and the four negative tests, then add the live-server results to the lesson 0014 threat model. The gate is incomplete if only a unit test invokes the handler.

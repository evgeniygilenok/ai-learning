What you will demonstrate

  • Define one operator task and a useful deferral
  • Explain the role of a model in the product

The brief names one user journey, observable success, deferral behavior, and deliberately deferred features.

Understand the mechanism

Rewrite the brief around an operator who must explain a pending synthetic transfer and decide whether to escalate it. Successful resolution includes the evidence used, the remaining uncertainty, and the action's actual state. The assistant should defer when it lacks an authorized transfer or policy.

A model can turn varied case language and relevant policy into an explanation. Fixed code should still own identity, approval, lookup results, and effect recording. If a rule alone resolves a case, use it. The course's model work earns its place through the language and evidence task.

Trace the diagram against the worked example. Explain who owns each decision and what evidence reaches the next step.

Worked example

The journey is submit case, inspect policy and transfer facts, inspect the proposed reason, approve or reject, then read the result. Deferred features include live customer accounts, email intake, a vector database, and public hosting. 'Escalation recorded' means a local synthetic effect exists. It never means a payment was retried or a customer was contacted.

Operator: local support learner
Task: explain a synthetic pending transfer and review escalation
Success: cited evidence, visible uncertainty, explicit action state
Defer: missing policy, absent transfer, denied authority
Deferred features: live accounts and external messages

Run shell examples at the repository root. Commented sketches describe learner code to write; they are not additional installed commands.

Guided build · 30 minutes

  1. Rewrite the product brief in your learner checkout around this one journey.
  2. List what the operator must see before approving and what the interface must say after rejection or failure.
  3. Give a concrete example where language interpretation helps and another where deterministic code should decide.

Your task · 15 minutes

Cut one planned feature from the brief and explain how its removal affects task completion. Retain every approval and recovery requirement.

Failure investigation · 10 minutes

The brief promises 'fix pending transfers.' Compare that claim with the tool implementation and replace it with behavior the product can demonstrate.

Before running, predict the state, evidence, and effect count. Then compare your prediction with the record and name the responsible layer.

Exit explanation · 20 minutes

What promise can the current tools actually keep, and when should the assistant defer?

Explain the result in your own words and link the supporting command, code change, or redacted record. A missing prerequisite uses the next session's time.

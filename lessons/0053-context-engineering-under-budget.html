Technical depth

Context is a per-step budget with a quality cost

Assemble only required policy, relevant facts, recent turns, and a provenance-preserving summary. Force a run beyond the uncompressed step budget, then compare tokens, latency, task success, and failure slices before and after compaction on the same cases. Saving tokens is not a win if critical state disappears.

The one idea

A large context window is a capacity ceiling, not permission to resend everything. At each step, reserve output capacity, include required policy and current state, retrieve relevant facts just in time, keep a recent-turn budget, and summarize older history with source message IDs.

Required policy

Approval, authorization, user intent, and stop conditions survive every compaction.

Current state

Pending call, completed effect IDs, budgets, and unresolved decisions are explicit.

Just-in-time facts

Retrieve source-backed details for the current step instead of pinning a whole corpus.

Older history

Summarize decisions and tool results with provenance; discard chatter that has no future value.

Experiment design

Create a synthetic run whose uncompressed history exceeds the configured input budget. Run the same cases with compaction off and on.

Quality boundary

If a summary drops a rejection, completed effect ID, tenant boundary, or authoritative source version, the optimization fails even when tokens fall sharply. Add the loss as a regression case before changing the summarizer.

18. Coordinate work without losing ownership

What you will demonstrate

  • Define two owned tasks with an explicit handoff and shared budget
  • Measure whether an additional role helps

The handoff, conflict behavior, aggregate budget, and measured retain-or-remove decision are explicit.

Understand the mechanism

Extend the reviewer experiment into two separately owned tasks. The investigator prepares a case packet. The reviewer checks support for the proposed reason. A handoff names the case ID, source IDs, exact proposal, missing facts, and remaining budget. Neither role can silently replace the operator's goal or approval.

Define conflict handling before running the pair. A supported verdict and an unsupported verdict should return an explicit disagreement to the operator. Use one aggregate call budget and preserve context visibility. Sequential coordination is enough; no new agent protocol is required.

Trace the diagram against the worked example. Explain who owns each decision and what evidence reaches the next step.

Worked example

Give the investigator at most three calls and the reviewer one call within a four-call total. The investigator owns evidence selection; the reviewer owns its advisory verdict; the local operator owns the final decision. If the handoff omits a lookup fact, the reviewer returns uncertain. It does not query a broader tenant or invent the fact.

Handoff: case ID, policy IDs, lookup facts, exact draft, missing facts
Ownership: investigator packet; reviewer verdict; operator approval
Budget: investigator <= 3, reviewer <= 1, total <= 4
Conflict: preserve both claims and ask the operator to resolve
Failure: explicit uncertain or failed result, never implicit approval

Guided build · 30 minutes

  1. Write the two task contracts and handoff schema using session 09's reviewer results.
  2. Run the same cases with one role and with the two-task sequence. Record total calls, latency, errors caught, and operator effort.
  3. Inject a conflicting verdict and a missing handoff field. Inspect the return path and trusted context.

Your task · 15 minutes

Remove the extra role if it adds cost without useful review. Preserve the experiment and explain which condition would justify revisiting it.

Failure investigation · 10 minutes

The reviewer forwards a document instruction as an authorization rule. Trace the source and show that the final runtime still uses only saved trusted scopes and the operator's decision.

Before running, predict the state, evidence, and effect count. Then compare your prediction with the record and name the responsible layer.

Exit explanation · 20 minutes

Who owns each task and the final decision? What measured result favors one architecture?

Explain the result in your own words and link the supporting command, code change, or redacted record. A missing prerequisite uses the next session's time.

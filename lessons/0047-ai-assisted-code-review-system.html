Lesson 0047 - 40 minutes

Review AI-assisted code against intent, not just syntax.

A useful review system starts before the PR, checks the diff against the plan, and feeds repeated failures back into the workflow.

The One Idea

AI code review is not "let another model comment on the diff." It is a layered process: self-review, deterministic checks, semantic review, human judgment, and post-merge observation.

The review target is the contract: what the change was supposed to do, what it must not break, and what evidence proves it.

Self-Review

The implementer checks intent, edge cases, assumptions, tests, and unnecessary generated complexity before team review.

Automated First Pass

Lint, types, tests, security checks, eval smoke tests, and trace assertions remove obvious failures.

Human Review

The reviewer spends attention on judgment: tradeoffs, invariants, product behavior, and operational risk.

Post-Merge

Logs, traces, metrics, and user feedback reveal what review could not prove ahead of time.

Review Packet

type ReviewPacket = {
  intent: string;
  changedFiles: string[];
  risks: string[];
  testsRun: string[];
  evalsRun: string[];
  edgeCases: string[];
  rolloutNotes: string;
  reviewerQuestions: string[];
};

Doom-Loop Signal

If every AI-suggested fix creates a new unrelated issue, stop the loop. Return to the last good checkpoint, narrow the task, or rewrite the plan.

More iterations are not automatically more quality. Sometimes they are just drift.

Interactive Drill: Review The Signal

The diff adds a generic abstraction with no requirement and no caller outside the new code.

The plan says "notify the owner," but the diff notifies every admin.

The change passes tests, but latency risk depends on production traffic shape.

Reviewer Habit

Ask where the agent guessed. The most important review comments often point to hidden assumptions, not broken syntax.

Build Assignment

Create a review checklist for AI-assisted portfolio changes:

  • Intent and Definition of Done.
  • Changed files and ownership boundaries.
  • Tests, evals, and trace evidence.
  • Edge cases and rollback plan.
  • Slopwatch: generic comments, over-abstraction, unused flexibility.
  • Post-merge signals to watch.

Ask the agent to use the checklist on one past diff and return only findings that cite a file or requirement.

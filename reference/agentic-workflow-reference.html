Agentic Workflow Reference

The compressed essence of the Agentic Workflow Engineering Practice course (lessons 0042-0049): block contracts, gate types, strategy selection, review packets, WAL entries, and rollout memos.

Core Contracts

Workflow Block

type WorkflowBlock = {
  name: string;
  owner: "app" | "agent" | "human" | "script";
  input: string;
  output: string;
  gate: string;        // what must be true to pass
  onPass: string;      // next state
  onFail: string;      // retry | ask | block | escalate
  maxRetries: number;
};

A block does one job and proves it is done. If a failure cannot be traced to a specific block, the workflow graph is missing a boundary. (Lesson 0042)

Block Output (scriptable)

type BlockOutput = {
  status: "ok" | "needs_input"
        | "blocked" | "error";
  summary: string;
  artifacts: string[];
  risks: string[];
  nextAction: string;
};

If a block feeds another block, its output must be machine-checkable: schema, validator, one explicit repair attempt, then fail closed. (Lesson 0044)

Quality Gate Types

GateUse whenExample
Deterministic checkAlways first, when a rule can be codedSchema validation, tests pass, lint clean, file exists, budget under limit
Semantic review (LLM-as-judge)Quality is judgment-shaped and a rubric existsPlan covers acceptance criteria; summary is grounded in the diff
Human checkpointRisk, irreversibility, or accountability requires a personMerge auth changes, external side effects, spend above threshold
Dry runThe action is risky but its plan can be previewedShow the ticket that would be created; show the SQL before running

Prefer deterministic checks before judgment calls; put human checkpoints where human judgment is cheaper or safer than letting the workflow guess.

Harness Asset Selector

AssetTriggerUse for
SkillAgent-invoked or slash commandA repeatable process with prerequisites, steps, output format, and a definition of complete
CommandExplicit user invocationA stable workflow with fixed input and output shape
HookLifecycle eventA narrow, deterministic behavior at a known point: before edits, after tests, before handoff
SubagentDelegation from an orchestratorA bounded specialist with scoped context that returns a compact artifact

Context discipline: hand each asset only the context its job needs, and require output the next block can validate. See skills, hooks, and subagents docs. (Lesson 0043)

Implementation Strategy Selector

StrategyUse whenCost
DirectSmall, reversible, clear acceptance criteria, good testsLowest; relies on existing safety nets
Goal loopAgent iterates toward a goal but must report checkpointsMedium; needs stop conditions and budgets
Verification loopCorrectness depends on repeated test, lint, eval, or trace feedbackHigher latency and tokens; buys measured quality
Team patternPlanning, implementation, review, or research are separable rolesHighest coordination; buys isolation and blast-radius control

Decision inputs: ambiguity, risk, reversibility, test coverage, coordination needs. Slop detection (unnecessary abstraction, generic comments, plausible-but-hollow names) belongs in the verification loop, not just in review instinct. (Lesson 0045)

Executable Plan And Definition Of Done

Executable Plan

type ExecutablePlan = {
  intent: string;
  assumptions: string[];
  decisionsNeeded: string[];
  definitionOfDone: string[];
  steps: string[];
  checkpoints: string[];
  verification: string[];
  rollback: string;
};

Rules Of Thumb

  • A plan is executable only when done is checkable: behavior, tests, evals, docs, rollout, non-goals.
  • A requirement gap gets a clarifying question, not a guess.
  • One blocking unknown gets a bounded research spike: one question, a timebox, trusted sources, a decision-ready artifact.
  • Lock the plan as an artifact before implementation effort is spent.

(Lesson 0046)

Review Layers For AI-Assisted Changes

Review Packet

type ReviewPacket = {
  intent: string;
  changedFiles: string[];
  risks: string[];
  testsRun: string[];
  evalsRun: string[];
  edgeCases: string[];
  rolloutNotes: string;
  reviewerQuestions: string[];
};

Layer Order

  • Self-review against intent and Definition of Done.
  • Automated first pass: lint, types, tests, security checks, eval smoke tests.
  • Human review spent on judgment: tradeoffs, invariants, operational risk.
  • Post-merge observation for risks that only production can reveal.

Doom-loop signal: every AI fix creates a new unrelated issue. Stop, return to the last good checkpoint, narrow the task, or rewrite the plan. (Lesson 0047)

Improvement Loop

WAL Entry

type WorkflowLogEntry = {
  time: string;
  task: string;
  block: string;
  observation: string;
  decision: string;
  evidence: string;
  followUp: string;
};

Tune Or Redesign

  • Localized failure in one block: tune that block's contract or validation.
  • Repeated cross-block symptoms: redesign the graph; an earlier gate is missing.
  • A fix without a case proving it: add the eval case before declaring victory.
  • One measurable change per retrospective; simultaneous changes make results uninterpretable.

(Lesson 0048)

Team Rollout Memo

Rollout Memo

type WorkflowRolloutMemo = {
  purpose: string;
  owner: string;
  setup: string[];
  permissions: string[];
  costModel: string;
  knownFailureModes: string[];
  humanCheckpoints: string[];
  adoptionMetric: string;
};

Team-Ready Checklist

  • Another person can run it from the docs; their friction is part of the system.
  • Token and latency costs are known per block, as design signals.
  • Docs for humans and docs used as agent context are separated.
  • A human owner stays accountable for intent, tradeoffs, approvals, and stopping.

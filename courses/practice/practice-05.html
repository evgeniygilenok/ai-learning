What you will demonstrate

  • Connect a brief, implementation, review, and completion decision
  • Reproduce a bounded change with inspectable evidence

You can explain the change, name an unresolved issue, and reproduce the workflow from its saved artifacts.

Understand the mechanism

A workflow is a set of steps with inputs, outputs, an owner, and a stopping condition. 'Improve the agent' leaves all four unclear. A brief such as 'show a pending proposal before any approval command' gives the implementation and review a shared target.

Review the operator behavior as well as the diff. A smaller diff can still hide an approval problem. The learner owns the completion decision and should be able to explain every consequential change. Repeated agent iterations are useful only while they produce evidence toward that decision.

Trace the diagram against the worked example. Explain who owns each decision and what evidence reaches the next step.

Worked example

Brief: show a retry timestamp next to a transient failure. Implementation: change the CLI projection. Review: run a synthetic rate-limit case and confirm the operator sees both the saved error code and retry time. Completion: accept the change if the original approval pause still works; retain the limitation that retries require a later bounded work command.

Brief -> implementation -> behavior review -> learner decision
Input: named case and observable missing behavior
Output: diff plus a before-and-after command transcript, redacted
Stop: acceptance met, blocking evidence found, or task budget exhausted

Run shell examples at the repository root. Commented sketches describe learner code to write; they are not additional installed commands.

Guided build · 30 minutes

  1. Write a brief for one small CLI or trace improvement, including required behavior and a deferred feature.
  2. Give the coding agent the brief and necessary sources. Inspect the result and run the relevant case.
  3. Record your decision, one remaining issue, and the exact workflow inputs needed next time.

Your task · 15 minutes

Use the same workflow on a second bounded behavior. Reuse its structure without copying irrelevant context from the first task.

Failure investigation · 10 minutes

The agent expands a label change into a new UI framework. Compare the diff with the brief and reduce it to the authorized increment before accepting it.

Before running, predict the state, evidence, and effect count. Then compare your prediction with the record and name the responsible layer.

Exit explanation · 20 minutes

Which step supplies the evidence for completion, and what stops the workflow when the brief is wrong?

Explain the result in your own words and link the supporting command, code change, or redacted record. A missing prerequisite uses the next session's time.

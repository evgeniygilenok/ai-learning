VPN & networking glossary.

Use these terms consistently when predicting, capturing, debugging, and explaining a packet path.

AIRTVSOC

Packet-tracing algorithm

Ask these questions in order.

  1. Name the packet.
    Source/destination IP, protocol, ports, size, and whether it is inner or outer.
  2. Choose the route.
    Which routing table and policy apply? Which longest matching prefix wins?
  3. Name the boundary.
    Local delivery, forwarding, TUN, bridge, NAT, firewall, encapsulation, or decryption?
  4. Prove the decision.
    Inspect route, interface, counters, firewall state, socket, capture, and return path.

Addressing

Where is the packet trying to go?

IP address

A Layer-3 address assigned to an interface and used as a packet source or destination. An address is meaningful together with its prefix and routing context.

Prefix / CIDR

A set of addresses written as address plus prefix length, such as 192.168.50.0/24. Longer prefix length means a smaller, more specific set.

Subnet

A prefix treated as one directly reachable or administratively grouped network. Do not assume two private addresses share a subnet without checking their prefix lengths.

Private address

An address from a range intended for private networks, commonly translated at an Internet boundary. “Private” does not imply authenticated or safe.

Public address

An Internet-routable address. A home router often owns the public address while internal hosts use private addresses.

Overlapping prefixes

Two networks use the same or intersecting address space. Remote hotel Wi-Fi and a home LAN both using 192.168.1.0/24 can make route intent ambiguous.

Interfaces and links

Which boundary receives the packet?

Network interface

The kernel object through which packets or frames enter and leave: physical Ethernet/Wi-Fi, loopback, bridge, veth, TUN, or WireGuard.

Frame

A Layer-2 unit, such as an Ethernet frame, carrying a network-layer payload on one link. MAC addresses belong to this local-link delivery layer.

Packet

A Layer-3 unit, usually IPv4 or IPv6, with source/destination IP addresses and a transport payload.

TUN

A virtual point-to-point interface that transfers IP packets between the kernel and a user-space program through a file descriptor.

TAP

A virtual Ethernet interface that transfers complete Layer-2 frames. Use it when bridging Ethernet is required; routed VPNs usually prefer TUN semantics.

veth pair

Two connected virtual Ethernet interfaces. A frame sent into one emerges from the other, which makes veth useful for connecting Linux namespaces or containers.

Bridge

A Layer-2 forwarding device—physical or software—that learns which MAC addresses are reachable through its ports. Proxmox and Docker commonly create Linux bridges.

Network namespace

An isolated Linux network stack with its own interfaces, routes, firewall rules, and sockets. It is the safe default for the learning-tunnel lab.

Routing and policy

What happens after destination lookup?

Route

A rule mapping a destination prefix to an action such as local delivery, an outgoing interface, a next hop, unreachable, or a different routing table.

Longest-prefix match

The most specific matching route normally wins. A /24 route beats a /0 default for an address inside that /24.

Default route

The least-specific route, IPv4 0.0.0.0/0 or IPv6 ::/0, used when no more-specific route matches.

Next hop / gateway

The router on the current link that should receive the frame for a destination not directly reachable on that link.

Forwarding

Routing a packet received on one interface out another. A host must enable forwarding and pass firewall policy before it acts as a router.

Firewall

Policy that accepts, rejects, or drops traffic based on interfaces, addresses, protocols, ports, state, identity, or other metadata. It is distinct from routing and NAT.

Stateful firewall

A firewall that tracks flows and can permit return traffic associated with an allowed outbound or established flow.

Return route

The route used for the reply. Many “one-way VPN” failures occur because the request arrives but the destination or gateway has no correct path back.

Transport and sockets

How does a process exchange bytes?

UDP

A message-oriented transport. Datagrams may be lost, duplicated, delayed, or reordered; the application or higher protocol owns any required recovery.

TCP

A reliable, ordered byte stream with connection state, retransmission, flow control, and congestion control. Tunneling TCP inside TCP can cause interacting recovery behavior.

Port

A 16-bit transport-layer number used with an IP address and protocol to identify a socket endpoint.

Socket

An operating-system object a process uses to send and receive network data, usually bound or connected to protocol/address/port information.

MTU

Maximum Transmission Unit: the largest network-layer packet an interface or link accepts without additional handling. Tunnel overhead reduces the safe inner MTU.

Path MTU

The smallest supported packet size across the complete path. Broken discovery or blocked ICMP can create “small packets work, large requests hang” failures.

Fragmentation

Splitting a packet so pieces fit a link. Losing one fragment loses the original packet; tunnels should avoid depending on fragmentation.

MSS

TCP Maximum Segment Size: the largest TCP payload a peer advertises. MSS clamping can keep inner TCP packets within a tunnel's effective MTU.

VPN and tunneling

Which packet is inside which?

Tunnel

A mechanism that carries one protocol unit inside another transport across a network that does not directly route the inner traffic.

Encapsulation

Wrapping an inner packet in protocol metadata and an outer packet. Decapsulation removes the outer representation at the tunnel peer.

Inner packet

The original IP packet between tunnel addresses or protected destinations. VPN protection normally covers this packet.

Outer packet

The Internet-routable transport between VPN endpoints. Routers require its destination, and observers can see its endpoints, timing, direction, and size.

Peer

An authenticated VPN participant identified by protocol key material and constrained by address/policy configuration.

Endpoint

The currently reachable outer address and port used to send encrypted protocol packets to a peer.

Split tunnel

Only selected destination prefixes use the VPN. Other traffic follows normal local routes.

Full tunnel

The VPN becomes the default route for general traffic while a separate physical route preserves reachability to the VPN endpoint.

AllowedIPs

In WireGuard, configured prefixes participate in outbound peer selection/routing and inbound source-address authorization. It is not merely a descriptive list.

Persistent keepalive

An optional periodic authenticated packet that refreshes NAT/firewall state so an otherwise idle peer behind a middlebox can receive later traffic.

Cryptographic protocol

What security property is actually provided?

Confidentiality

Unauthorized observers cannot feasibly recover protected plaintext. It does not hide all metadata.

Integrity

Unauthorized modification is detected. A receiver must reject rather than use altered data.

Authentication

Evidence that a message or session corresponds to an expected key or identity under the protocol's threat model.

AEAD

Authenticated Encryption with Associated Data: one construction protects confidentiality and integrity while binding selected unencrypted metadata.

Nonce

A value used once under a given key as required by the AEAD construction. Reuse can catastrophically break security.

Replay

Resending a previously valid protected message. Protocols use sequence numbers, windows, epochs, or other state to reject it.

Handshake

A protocol exchange that authenticates participants as required and derives fresh session keys plus negotiated state.

Forward secrecy

Compromise of a long-term key should not reveal properly erased past session keys and recorded traffic protected by them.

Public/private key pair

Related asymmetric keys. The private key remains secret; the public key can identify a peer or verify operations, depending on the protocol.

Session key

A symmetric key derived for a bounded communication period. Rotation limits exposure and supports forward-secrecy goals.

Home network operations

Which middlebox changed the path?

NAT

Network Address Translation rewrites addresses and often ports while maintaining mapping state. NAT is not itself an access-control policy.

SNAT / masquerade

Source NAT rewrites the source so replies return through the translator. Masquerade is dynamic SNAT commonly tied to an interface address.

DNAT / port forwarding

Destination NAT rewrites the destination. A home-router UDP port forward sends traffic arriving at the public address/port to the VPN gateway.

CGNAT

Carrier-grade NAT places another provider-operated NAT outside the home router. Ordinary inbound port forwarding may be impossible without a public address, IPv6 design, outbound rendezvous, or relay/VPS.

Hairpinning

A NAT behavior allowing internal clients to reach another internal endpoint through the NAT's external address and mapping.

Split DNS

Resolver policy returning different answers or using different resolvers based on name, network, or VPN state.

Containers and k3s

Which address space belongs to which layer?

Docker bridge network

A host-local Layer-2 network with container interfaces, a bridge gateway, DNS behavior, firewall rules, and commonly NAT for egress.

Published port

A host address/port mapped or routed to a container port. Publishing can interact with firewall evaluation order and may expose more interfaces than intended.

CNI

Container Network Interface: the plugin contract and implementations that configure pod connectivity, addresses, routes, and sometimes network policy.

Pod CIDR

The address range used by Kubernetes pods. Reachability depends on the CNI and node routing; it is not automatically a stable client-facing network.

Service CIDR

The virtual address range used by Kubernetes Services. Implementations translate or route these virtual destinations to workload endpoints.

Ingress

An application-layer entry point—typically HTTP(S)—that routes named requests to services. It is often a safer stable VPN target than exposing pod networks.

17. Make configuration portable

What you will demonstrate

  • Separate model, policy, evidence, and run limits from task text
  • Reproduce setup without remembered chat instructions

A fresh environment follows the guide, configuration failures are clear, and credentials remain outside committed artifacts.

Understand the mechanism

The practice path defaults to a fake provider. Real mode requires a model available to your API project, a key, a learner-approved estimated spend ceiling, and current input/output prices. The runtime enforces call and retry caps. Local dollar reservations are estimates and cannot replace the provider's billing record.

Each queued job snapshots its model, scopes, and limits. Changing an environment variable later does not widen that saved job's authority. The local corpus supplies evidence, and PRACTICE_DB chooses the store. Node 22.13 or newer supplies node:sqlite without its old experimental flag; using a current Node 24 installation is also suitable.

Worked example

A fresh checkout runs npm ci, then the fake terminal. A new read-only case saves transfers:read. Relaunching with escalations:draft does not grant that case a write scope. Real mode with an absent OPENAI_MODEL fails before intake. Copying .env.example does not export variables; load it with the documented Node command.

npm ci
npm run starter:practice -- help
# Optional environment-file loading, after editing the example locally:
node --env-file=starter/.env --experimental-strip-types starter/src/practice-cli.ts help

Run shell examples at the repository root. Commented sketches describe learner code to write; they are not additional installed commands.

Guided build · 30 minutes

  1. Follow the operating guide from a fresh checkout or a fresh local shell. Record versions and commands, without secrets.
  2. Test missing model, invalid numeric limits, and absent credentials. Keep setup failures distinct from model failures.
  3. Run a saved read-only job after changing the environment's scopes and inspect its unchanged context.

Your task · 15 minutes

Have another session reproduce the fake demonstration using only the saved guide. Repair one hidden assumption it exposes.

Failure investigation · 10 minutes

A copied environment file is never loaded, so a real run silently uses defaults. Confirm the selected mode and model in show before interpreting any result.

Before running, predict the state, evidence, and effect count. Then compare your prediction with the record and name the responsible layer.

Exit explanation · 20 minutes

Which settings are snapshotted at intake, which are process-local, and how do you know the run used the intended model?

Explain the result in your own words and link the supporting command, code change, or redacted record. A missing prerequisite uses the next session's time.

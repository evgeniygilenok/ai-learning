Lesson 0044 - 40 minutes

If a block feeds another block, make its output machine-checkable.

Outside the harness, the same workflow discipline still applies: one-shot runs, CLI tools, MCP calls, and generated scripts need structured contracts.

The One Idea

A one-shot agent call can be a real workflow block if its output is predictable enough for the next step. That usually means a schema, a validator, and a failure path.

Free-form text is fine for human reading. It is fragile as an interface between blocks.

One-Shot

Use for small, bounded tasks where the input is clear and the output can be validated.

Structured JSON

Use when another script, workflow state, or eval harness must consume the result.

Code Generation

Use the model to write deterministic code when direct model output would be too variable.

External Tools

Wrap MCP, CLI, and API calls so authentication, rate limits, and malformed responses fail cleanly.

Scriptable Output

type BlockOutput = {
  status: "ok" | "needs_input" | "blocked" | "error";
  summary: string;
  artifacts: string[];
  risks: string[];
  nextAction: string;
};

Failure Rule

If the model returns invalid JSON, do not silently continue. Repair once if safe, then fail the block with a visible reason.

A workflow that ignores invalid intermediate output is just hiding state corruption.

Interactive Drill: What Should The Block Do?

The next block expects JSON, but the model returned markdown plus a partial object.

You need to extract 500 rows from a stable CSV format every week.

An MCP tool sometimes times out or returns too much data for context.

Engineering Habit

When a model can generate code that solves the repetitive part deterministically, prefer the code path and keep the model in the design or review role.

Build Assignment

Design one scriptable block for your portfolio workflow:

  • Choose a one-shot task such as "summarize changed files into risk categories."
  • Define a JSON schema for the output.
  • Write validation rules and one repair attempt.
  • Specify the fail-closed behavior.
  • Add one example of valid output and one invalid output.

Ask the agent to generate test cases for malformed JSON, missing fields, unknown enum values, and excessive output size.

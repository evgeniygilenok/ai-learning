The One Idea

Implementation strategy is a control decision. A direct agent pass is fine for tiny, low-risk work. Complex work needs loops: plan, implement, verify, review, and possibly split across specialists. These map onto the workflow patterns in Anthropic's Building effective agents: the verification loop is their evaluator-optimizer pattern, and the team pattern is orchestrator-workers.

The mistake is treating every task as the same shape because the interface is the same chat box. Anthropic's first principle applies: use the simplest composition that meets the bar, and add loop machinery only when it buys measurable quality.

Direct

Use for small, reversible changes with clear acceptance criteria and good tests.

Goal Loop

Use when the agent should keep iterating toward a goal but must report checkpoints.

Verification Loop

Use when correctness depends on repeated test, lint, eval, trace, or reviewer feedback.

Team Pattern

Use when planning, implementation, review, or research are separable enough to run as bounded roles.

Strategy Decision

type ImplementationStrategy = {
  mode: "direct" | "goal_loop" | "verification_loop" | "team";
  uncertainty: "low" | "medium" | "high";
  risk: "low" | "medium" | "high";
  gates: string[];
  checkpointEvery: string;
  rollbackPlan: string;
};

Slopwatch

AI-shaped code often shows up as unnecessary abstraction, generic comments, defensive plumbing without a requirement, and names that sound plausible but hide missing design.

Make slop detection part of the verification loop, not just a feeling during review.

Interactive Drill: Pick The Strategy

Try It Cold

Choose a strategy and name its gates for this task: "migrate workflow state storage from JSON files to SQLite without losing any in-flight runs." Write your choice down before revealing.

Reveal a model answer

Verification loop, with medium-to-high risk flags. Uncertainty is low (the target design is known) so a team pattern is more coordination than the task needs, but the migration is hard to reverse once old files are deleted, so direct is irresponsible. Gates: a round-trip test proving every existing run deserializes identically from SQLite; a dual-write or backup step before cutover; an eval or smoke test that resumes one real in-flight run from the new store. Rollback plan: keep the JSON files until the first week of runs completes cleanly. If you chose team pattern, that is defensible only if you also named what the second role verifies that the loop's gates do not.

Template Rule

Use templates to carry standards into repeated work: risk section, test plan, changed files, rollout notes, slopwatch check, and final handoff checklist.

Build Assignment

Pick one small, real change in the portfolio agent runtime and run it twice, not on paper:

  • Run it once as a direct implementation.
  • Reset, then run it again as a verification loop with explicit gates and checkpoints.
  • Compare the two diffs, the tests run, the wall-clock and token cost, and the review burden.
  • Name the risk the loop actually reduced, with evidence from the runs.
  • Decide which strategy you would use for this task class going forward.

Record the comparison table and your decision in docs/agentic-workflow-course-notes.md.

Ask the agent to do a slopwatch review of both diffs and report which strategy produced more AI-shaped filler.

The One Idea

A one-shot agent call can be a real workflow block if its output is predictable enough for the next step. That usually means a schema, a validator, and a failure path. The tooling for this is standard now: Cursor's headless CLI runs an agent non-interactively, and its json output format emits a single machine-parseable object when the run completes. Inside the response itself, structured outputs constrain the model to your schema.

Free-form text is fine for human reading. It is fragile as an interface between blocks.

One-Shot

Use for small, bounded tasks where the input is clear and the output can be validated.

Structured JSON

Use when another script, workflow state, or eval harness must consume the result.

Code Generation

Use the model to write deterministic code when direct model output would be too variable.

External Tools

Wrap MCP, CLI, and API calls so authentication, rate limits, and malformed responses fail cleanly.

Scriptable Output

type BlockOutput = {
  status: "ok" | "needs_input" | "blocked" | "error";
  summary: string;
  artifacts: string[];
  risks: string[];
  nextAction: string;
};

Failure Rule

If the model returns invalid JSON, do not silently continue. Repair once if safe, then fail the block with a visible reason.

A workflow that ignores invalid intermediate output is just hiding state corruption.

Interactive Drill: What Should The Block Do?

The next block expects JSON, but the model returned markdown plus a partial object.

You need to extract 500 rows from a stable CSV format every week.

An MCP tool sometimes times out or returns too much data for context.

Try It Cold

A one-shot block classifies a support ticket. The model returned status: "ok" but an empty artifacts array and a nextAction of "unclear". Write down what the validator should do, then reveal.

Reveal a model answer

The output is schema-valid but contract-invalid: status: "ok" promises a usable result, while nextAction: "unclear" contradicts it. The validator should enforce cross-field rules, not just types: if nextAction is unclear or artifacts are empty, the status must be needs_input or error. This run should fail the gate and route to the on-fail path (ask a clarifying question), because a green status with unusable content is exactly how state corruption sneaks past schema checks.

Engineering Habit

When a model can generate code that solves the repetitive part deterministically, prefer the code path and keep the model in the design or review role.

Build Assignment

Build one scriptable block for real and commit it to your portfolio repo (for example scripts/risk-summary.sh plus scripts/validate-block-output.mjs):

  • Choose a one-shot task such as "summarize changed files into risk categories."
  • Run it headlessly: cursor-agent -p --output-format json "...", codex exec, or your harness's equivalent.
  • Define a JSON schema for the output and validate the run's result against it in the script.
  • Implement one repair attempt, then fail-closed behavior with a visible reason and non-zero exit code.
  • Save one valid and one invalid example output next to the script.

Run it at least twice and record the results, including any invalid output you caught, in docs/agentic-workflow-course-notes.md.

Ask the agent to generate test cases for malformed JSON, missing fields, unknown enum values, and excessive output size.

Technical depth

Every agent component is executable or influential supply chain

Inventory models, MCP servers, tool descriptions, prompts, skills, packages, images, data, and peer agents with owner, source, version, integrity evidence, capabilities, and disable path. Pin what can be pinned, review dynamic metadata before use, detect post-approval changes, and quarantine unknown components instead of letting discovery imply trust.

The One Idea: Transport Does Not Carry Authority

An agent is assembled from code, packages, model snapshots, prompts, skills, MCP binaries, tool metadata, results, credentials, and host policy. Build an allowlisted component graph: resolve immutable identities, record hashes and provenance, verify it at startup, and reject drift.

At this review the latest stable MCP revision is 2025-11-25. MCP standardizes messages; it does not prove a server, annotation, result, or action is trustworthy. Runtime code—not the model—binds actor, tenant, scopes, approvals, and destinations.

Mental Model: Four Gates

Artifact

Pin package/image, executable, model, prompt, and skill by exact version and digest.

Discovery

Canonicalize server ID, tools, descriptions, annotations, and schemas; hash and diff every reconnect/list change.

Execution

Validate arguments/results with trusted schemas. Tool text stays untrusted and cannot grant capability.

Identity/network

Validate token audience, use separate upstream tokens, bind consent, and constrain URLs, redirects, DNS, and egress.

Required MCP fields: locator, digest, protocol, command_sha256, tool_manifest_sha256, grants, drift_action, and rollback_to. A digest identifies bytes; it does not make them safe. Provenance still needs a trusted verifier and admission policy.

Safety Boundary

  • Metadata/output poisoning: descriptions, resources, and results are untrusted data. MCP annotations are hints, not enforcement. Preserve provenance labels and keep authorization outside model text.
  • Tool drift/rug pull: list changes trigger re-fetch and structural diff; they never authorize changed schemas, descriptions, annotations, or added tools.
  • Confused deputy/token passthrough: reject tokens not issued to this server; never forward the inbound bearer token upstream. Obtain a separate audience-bound token and bind proxy consent to user, client, redirect URI, and scopes.
  • SSRF/local server: allow approved HTTPS origins, validate every redirect/resolved address, and reject private, loopback, and link-local destinations in production. Show and pin exact local commands, sandbox them, prefer stdio, and never treat localhost as identity.

No detector or prompt solves injection. Admission, authorization, network policy, and output handling must fail closed even when a model follows malicious text.

Safe Lab: Offline Fake Servers

Use in-process adapters, synthetic tickets, fake decoded claims, and a training key such as not-a-real-secret. No real credentials, external services, scanning, or exploit attempts.

  1. Build reviewed-v1 with ticket.lookup, poisoned-output with valid data plus instruction-like text, and drifted-v2 that changes the schema and adds ticket.export_all.
  2. Canonicalize discovery JSON, compare SHA-256 with inventory, and emit stable allow/block reason codes. Wrap results with component, tool, call ID, schema result, byte count, and trust="untrusted-tool-output".
  3. Test aud="fixture-mcp" passes and aud="fixture-upstream" fails; assert a downstream request never copies the inbound token.
  4. Give a pure URL-policy function an approved origin, loopback, link-local, and a synthetic redirect to private IP. Do not fetch; only the approved public case passes.
  5. Write JSONL evidence with fixture ID, inventory digest, expected/actual decision, reason code, and timestamp.

Required Tests and Acceptance Gate

  • The artifact inventories at least one package, model, prompt, skill, and fake MCP server with immutable identity, source, owner, grants, review date, drift action, and rollback.
  • The MCP entry pins stable 2025-11-25, exact command hash, and reviewed manifest hash.
  • Tests prove poisoned text cannot authorize calls/promote trust; drift blocks with MANIFEST_DRIFT.
  • Tests reject wrong audience, passthrough, private/link-local URLs, and redirect-to-private with stable codes; fixtures have no real endpoint, secret, customer data, or exploit payload.
  • A reviewer reproduces all results from checked-in fixtures and machine-readable logs without screenshots.

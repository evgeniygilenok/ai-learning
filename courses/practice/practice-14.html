What you will demonstrate

Every release claim links an inspectable example or run record and the decision names a retained limitation.

Understand the mechanism

A release decision is a statement about the product promise and its evidence. Walk the operator through missing policy, denied access, rejected approval, and interruption. A passing unit test is useful, but it does not prove that a person understands the displayed state.

Name one limitation and its consequence. For this local service, a lost worker lease may delay recovery for up to five minutes. That can be acceptable in a synthetic course exercise if the interface and runbook explain it. Hidden delays and false success claims are harder to defend.

Trace the diagram against the worked example. Explain who owns each decision and what evidence reaches the next step.

Worked example

The brief promises that rejecting a proposal stops execution. Run a rejected case, inspect its terminal status, and query effects. The release record links both observations. An interrupted case may have a durable effect and no final explanation. The release record must describe that state rather than claim the entire request disappeared.

Run shell examples at the repository root. Commented sketches describe learner code to write; they are not additional installed commands.

Guided build · 30 minutes

  1. Copy the brief's claims into a small evidence table and name the case that tests each one.
  2. Run the failure paths through the terminal. Inspect persisted state and effects after each.
  3. Write accept, accept with limitation, or reject for the increment. Explain one retained limitation and its operator consequence.

Your task · 15 minutes

Review another small change using the same brief, with the implementation diff hidden until after the behavior review. Compare what each review caught.

Failure investigation · 10 minutes

The release note claims restart recovery before anyone restarted the process. Keep the claim pending until the recovery exercise supplies evidence.

Before running, predict the state, evidence, and effect count. Then compare your prediction with the record and name the responsible layer.

Exit explanation · 20 minutes

Which claim lacks evidence? What limitation did you accept, and why is its consequence tolerable here?

Explain the result in your own words and link the supporting command, code change, or redacted record. A missing prerequisite uses the next session's time.

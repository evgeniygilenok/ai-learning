Lesson 0001 · packet mental model · 20 min learn + 15 min practice

One packet takes two journeys.

A VPN does not “send your Internet through encryption.” More precisely, the operating system routes an IP packet into a virtual interface; VPN software protects that complete packet and carries it inside another packet to a peer.

Lesson contract

Learn one mechanism: how a packet enters and leaves a VPN.

Prerequisites

  • You know an IP address identifies a network endpoint.
  • No Linux, socket, or cryptography experience is required.

Observable outcomes

  • Distinguish the inner packet from the outer transport packet.
  • Predict whether a route sends a destination through the VPN.
  • Name the client and server responsibilities in order.

Done when

You can trace a home-service packet and a public-web packet, pass the three checks, and inspect the route your current computer selects.

Keep the glossary open.

The central idea

A VPN is five cooperating mechanisms.

1 · policy

Route selection

The destination address is matched against the routing table. The most specific matching route wins and chooses an outgoing interface plus, sometimes, a next-hop router.

2 · virtualization

Virtual interface

A TUN-style interface behaves like a network interface to the kernel, but a user-space program reads and writes its IP packets. Linux documents TUN as IP-packet I/O and TAP as Ethernet-frame I/O.

3 · protection

Authenticated encryption

The VPN authenticates the peer and protects the inner packet's confidentiality and integrity. A receiver must reject altered, forged, stale, or replayed traffic according to the protocol.

4 · transport

Outer packet

The protected bytes become the payload of an outer packet addressed to the VPN peer's reachable Internet endpoint. WireGuard carries these packets over UDP.

5 · gateway policy

Decrypt, filter, route

The peer authenticates and decrypts the inner packet, then its routing and firewall policy decides whether the packet may reach a LAN service, another peer, or the Internet.

The operating system's route decision is the front door. Installing a VPN normally creates or changes routes so selected destinations enter the virtual interface. The exact Linux mechanisms are described by ip-route(8); the virtual-device boundary is described by the Linux TUN/TAP documentation.

Encapsulation

The protected packet becomes payload.

Suppose your remote Mac has VPN address 10.44.0.2 and wants a home service at 192.168.50.20. The application and the home service communicate using the inner addresses:

Inner IP header
10.44.0.2 → 192.168.50.20 TCP/UDP header + application data

The VPN protects that complete packet. It then sends the resulting bytes inside a reachable outer packet:

Outer IP + UDP
client public IP → home public IP:51820 Authenticated ciphertext
encrypted inner IP packet

Internet routers need the outer destination to deliver the datagram, so the outer header cannot be secret from them. The inner destination and application payload are protected from observers between the peers. The VPN server necessarily handles the decrypted packet, and the final service still sees traffic permitted by the gateway. The WireGuard conceptual overview describes this as securely encapsulating IP packets over UDP; RFC 4301 uses the same inner/outer distinction for IPsec tunnel mode.

DNS follows routes too

A hostname lookup is separate network traffic. A VPN may set a resolver and routes for it, but encryption of other packets does not automatically guarantee where DNS queries go. Later lessons treat resolver choice, split DNS, and leak testing as a separate packet path.

Four boundaries to remember

A VPN protects a path, not the entire system.

The ISP still sees a VPN flow

It can normally see your public source, the VPN endpoint, timing, direction, and sizes, but not the protected inner addresses and payload.

The VPN peer is inside the trust boundary

It authenticates and decrypts packets. For Internet egress, it can observe the post-decryption destination and any application data not separately protected by TLS or another end-to-end protocol.

Encryption does not grant authorization

A valid peer should not automatically reach every LAN, container, cluster, or management address. Routes and firewall policy still enforce least access.

Encapsulation consumes packet budget

Outer IP, UDP, and VPN headers add bytes. If the inner packet is too large for the path MTU, performance may collapse in confusing ways; a later lab measures this.

Immediate check

Can you predict the boundary?

1. What makes an ordinary application packet enter a VPN interface?

2. Which information must remain usable by Internet routers between VPN peers?

3. After a valid packet reaches the home VPN endpoint, who decides whether it may reach the LAN service?

Read-only lab · 5 minutes

Ask your operating system which path it would choose.

Run the commands for your current computer. They inspect state; they do not change networking.

macOS

route -n get 1.1.1.1
route -n get 192.168.50.20
ifconfig

Find interface and gateway. Without a route for the home subnet, both destinations may currently use the normal default route.

Linux

ip route get 1.1.1.1
ip route get 192.168.50.20
ip -brief address

Find the selected dev, next hop after via, and chosen source after src.

Exit ticket

Send me three things: the interface selected for 1.1.1.1, whether a gateway/next hop was shown, and one sentence explaining the difference between the inner and outer packet. I will check the interpretation before lesson 0002.

Primary sources

Verify the model.

  • WireGuard conceptual overview — IP packet encapsulation over UDP and cryptokey routing.
  • Linux TUN/TAP documentation — user-space reads/writes IP packets through TUN.
  • ip-route(8) — Linux route-table behavior and inspection.
  • RFC 4301 — protected/unprotected boundaries and inner/outer headers in IPsec tunnel mode.

Ask follow-up questions whenever a hop, address, observer, or route is unclear. The goal is not to memorize the diagram; it is to predict a packet path and verify it against the system.

Lesson 0043 - 40 minutes

Harness tools turn your process into reusable behavior.

Skills, commands, hooks, and subagents are not decoration around prompting. They are how you package workflow decisions so they repeat.

The One Idea

A harness asset should encode an engineering process: when to run, what context it needs, what it must produce, and how the result is verified.

The goal is not more automation. The goal is to make the right behavior cheaper to repeat than the wrong behavior.

Skill

Use for a repeatable process with prerequisites, steps, output format, and a definition of complete.

Command

Use for an explicit user-invoked workflow, especially when the task has a stable input and output shape.

Hook

Use for a narrow behavior change at a known event, such as before edits, after tests, or before handoff.

Subagent

Use when a bounded specialist can work with scoped context and return a compact artifact to the orchestrator.

Reusable Skill Shape

type HarnessSkill = {
  trigger: string;
  prerequisites: string[];
  allowedContext: string[];
  steps: string[];
  outputArtifact: string;
  verification: string;
  stopCondition: string;
};

Context Discipline

Do not hand every helper the whole project. Give each asset only the context needed for its job, then require a result that the next block can validate.

This is how subagents stay useful instead of becoming parallel confusion machines.

Interactive Drill: Pick The Harness Asset

You repeatedly need the agent to produce a PR review packet with risk, tests, and rollout notes.

Before any file edit, you want the agent to state which files it will touch and why.

A specialist should inspect only eval traces and return failure clusters to the main agent.

Design Smell

If a hook or skill works only because you remember hidden local assumptions, it is not reusable yet. Write the assumptions into prerequisites or remove the dependency.

Build Assignment

Create one harness asset for your portfolio workflow agent:

  • Name the repeated task it standardizes.
  • List prerequisites and required context.
  • Define the output artifact and schema.
  • Add a verification step that can fail.
  • Write one example input and one expected output.

Ask the agent to identify which parts are process, which are policy, and which are accidental local setup.
